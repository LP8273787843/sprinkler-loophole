The Sprinkler Loophole

The case file

What is supposed to happen?

The sprinkler should only switch on when all three of these are true at the same time:

⏰ It's watering time

Morning 5:00 to 8:00 or evening 18:00 to 20:00 (6 pm to 8 pm).

☀️ No rain today

If it already rained, the plants don't need more water.

🌱 Soil is dry

Soil wetness must be below 40%.

The problem: the sprinkler is turning on in the middle of the afternoon. Someone made a mistake in the code. Our job is to find it, prove it, fix it, and check the fix really works.

The broken code (from our problem card)

Input: hasRained, moistureLevel, currentHour
morningWindow ← (currentHour ≥ 5  OR  currentHour < 8)
eveningWindow ← (currentHour ≥ 18 OR  currentHour < 20)
goodTime      ← morningWindow OR eveningWindow
if NOT hasRained AND moistureLevel < 40 AND goodTime
   then output "ON" else "OFF"
Step 1 · Trace by hand (no AI yet)

Let's pretend to be the computer at 2 pm

"Tracing" means going through the code one line at a time, like a computer does, and writing down each answer. Our test: hasRained = False, moistureLevel = 20, currentHour = 14 (2 pm).

Clue found! The code says ON at 2 pm. But 2 pm is not in the morning window or the evening window, so it should be OFF. The windows are saying "yes" when they should say "no".
Step 2 · Why is it broken?

OR vs AND: the tiny word that broke the garden

OR

"Is at least one of these true?" If even one part is true, the answer is yes.

Example: "You can have juice OR milk." One is enough.

AND

"Are both of these true?" Every part has to be true, or the answer is no.

Example: "You need a ticket AND a seat." You need both.

Try it. Every hour of the day is a box. A blue dot means "hour is 5 or later". An orange dot means "hour is before 8". The green boxes show when the morning window says yes.

The big idea: every hour is either "5 or later" or "before 8". There is no hour that is neither. So with OR, the morning window is true all 24 hours. Same for the evening window. That means "good time" is always true, and the time check does nothing at all.
Step 3 · The fix

Change two words. Leave the third one alone.

"Between 5 and 8" means the hour must be 5 or later AND before 8. Both parts must be true. So we swap OR for AND inside each window.

Input: hasRained, moistureLevel, currentHour
morningWindow ← (currentHour ≥ 5  AND currentHour < 8)    // was OR
eveningWindow ← (currentHour ≥ 18 AND currentHour < 20)   // was OR
goodTime      ← morningWindow OR eveningWindow           // keep OR!
if NOT hasRained AND moistureLevel < 40 AND goodTime
   then output "ON" else "OFF"

Trap question! 🪤

Some people (and some AI tools) see the OR on the goodTime line and change that one to AND as well. Should we?

Step 4 · Our three AI prompts

What we asked the AI, and what we got back

Copy each prompt into ChatGPT, Claude or Gemini. Under each one is the correct answer, so you can check if the AI got it right.

Prompt 1 · Trace & Diagnose
Trace this pseudocode by hand for hasRained = False, moistureLevel = 20, currentHour = 14 (2pm). Do the sprinklers turn on? Should they, at 2pm? morningWindow ← (currentHour ≥ 5 OR currentHour < 8) eveningWindow ← (currentHour ≥ 18 OR currentHour < 20) goodTime ← morningWindow OR eveningWindow if NOT hasRained AND moistureLevel < 40 AND goodTime then output "ON" else "OFF"

Correct answer:

  • morningWindow = (14 ≥ 5 → TRUE) OR (14 < 8 → FALSE) = TRUE
  • eveningWindow = (14 ≥ 18 → FALSE) OR (14 < 20 → TRUE) = TRUE
  • goodTime = TRUE OR TRUE = TRUE
  • NOT hasRained = TRUE, 20 < 40 = TRUE → output "ON"

Should it? No. 2 pm is outside both windows, so it should be "OFF". The bug is proven.

Prompt 2 · Propose a Fix
morningWindow and eveningWindow should only be True inside their specific hour ranges, but they're True almost all day. Find and fix the operator error. Input: hasRained, moistureLevel, currentHour morningWindow ← (currentHour ≥ 5 OR currentHour < 8) eveningWindow ← (currentHour ≥ 18 OR currentHour < 20) goodTime ← morningWindow OR eveningWindow if NOT hasRained AND moistureLevel < 40 AND goodTime then output "ON" else "OFF"

Correct answer: change the OR inside each window to AND:

morningWindow ← (currentHour ≥ 5 AND currentHour < 8)
eveningWindow ← (currentHour ≥ 18 AND currentHour < 20)

The goodTime line stays OR, because the sprinkler can run in the morning or the evening.

What to watch for: if the AI also changes goodTime to AND, or rewrites lots of other lines, it has gone too far. Our job is a minimal fix.

Prompt 3 · Verify the Fix
Verify your fix by tracing it line by line for currentHour = 6 and currentHour = 19, with hasRained = False and moistureLevel = 20. Both should output "ON". Also trace currentHour = 14, which should now output "OFF". Show every True/False value, don't just tell me it works.

Correct answer:

  • Hour 6: morning = (6≥5 TRUE) AND (6<8 TRUE) = TRUE → goodTime TRUE → ON ✅
  • Hour 19: evening = (19≥18 TRUE) AND (19<20 TRUE) = TRUE → goodTime TRUE → ON ✅
  • Hour 14: morning = (14≥5 TRUE) AND (14<8 FALSE) = FALSE, evening = (14≥18 FALSE) AND (14<20 TRUE) = FALSE → goodTime FALSE → OFF ✅

We added "show every value" to the prompt on purpose, so the AI has to actually trace and can't just say "looks good".

Step 7 · Present & defend (2 minutes)

Our presentation script

2:00
0:00
The flaw. "Our garden sprinkler should only run 5 to 8 in the morning or 6 to 8 in the evening, when it's dry. It was turning on at 2 pm. We traced 2 pm by hand: 14 is 5 or later is true, so with OR the whole morning window became true. The mistake was OR where it should say AND."
0:30
The fix in plain English. "Being 'between 5 and 8' means you have to be 5 or later and before 8. Both have to be true. So we changed OR to AND in the two window lines. We kept the OR that joins morning and evening, because either window is fine."
1:00
An edge case we checked. "We tested exactly 8 am. The fixed code says OFF, because 8 is not less than 8. That matches the window ending at 8:00. We also tested 2 am. The broken code said ON at 2 am too, so the bug was much bigger than just the afternoon. The fix says OFF."
1:30
What the AI oversimplified. "The problem card says the windows are true 'almost all day'. That's not quite right. With OR they are true every single hour, so the time check did nothing at all. We caught this by testing all 24 hours, not just 2 pm. We also watched for the AI changing the goodTime OR to AND, which would stop the sprinkler from ever running."

Debrief question: which kind of flaw is hardest to catch?

Our answer: the off-by-one boundary (Team D's kind). A wrong operator like ours shows up as soon as you test one normal afternoon hour. A boundary bug only shows up if you test the exact edge value, like a password of exactly 8 letters. Most people test "normal" values first, so edge bugs slip through. Ours was still sneaky, because "5 or 8" sounds fine when you say it out loud.
